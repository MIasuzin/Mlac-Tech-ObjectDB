# MTDB API

MTDB — встроенное синхронное хранилище JSON-документов для Node.js. Данные находятся в одном файле `.mtdb`; каталоги существуют внутри базы.

```js
const mtdb = require('@mlasuzin/mtdb');
const db = mtdb.open('./data.mtdb');

try {
  db.mkdir('users');
  db.write('users/42.json', {id: 42});
  console.log(db.read('users/42.json'));
}

finally {
  db.close();
}
```

Требуется Node.js 18 или новее. Все методы синхронны и могут блокировать поток Node.js на время работы с файлом. Один файл базы одновременно открывает только один процесс-писатель. Публичного режима параллельного чтения другим процессом нет.

## Методы

| Метод | Возвращает | Назначение |
| --- | --- | --- |
| `mtdb.open(filePath)` | объект базы | Открыть существующую базу v3 или создать новую |
| `db.mkdir(path)` | `boolean` | Создать каталог и отсутствующих родителей |
| `db.rmdir(path, options?)` | `boolean` | Удалить пустой каталог или рекурсивно удалить поддерево |
| `db.has(path)` | `boolean` | Проверить существование документа или каталога |
| `db.list(path, options?)` | `string[]` | Получить пути JSON-документов |
| `db.read(path)` | JSON-значение или `undefined` | Прочитать документ |
| `db.write(path, value)` | `true` | Создать или перезаписать документ |
| `db.delete(path)` | `boolean` | Удалить документ |
| `db.transaction(handler)` | результат `handler` | Зафиксировать несколько изменений вместе |
| `db.verify()` | объект проверки | Проверить весь файл |
| `db.stats()` | объект статистики | Проверить файл и получить статистику |
| `db.close()` | `boolean` | Закрыть базу и освободить блокировку |

`db.compact()` в публичном API **нет**. Компактизация запускается автоматически в фоновом потоке, когда накопилось достаточно устаревших данных. Её ошибка доступна через `db.stats().maintenanceError`.

## Пути и данные

- `path` внутри базы — строка; `\` заменяется на `/`, пробелы по краям пути и каждого сегмента удаляются, пустые сегменты и `.` пропускаются. Например, `users//./42.json` становится `users/42.json`.
- Сегмент `..`, абсолютный путь, путь с буквой диска и управляющие символы запрещены. Регистр символов сохраняется. Ограничение исходного пути — 1024 байта UTF-8.
- Для `read()`, `write()`, `delete()` и соответствующих методов транзакции требуется суффикс `.json` без учёта регистра. Каталоги не создаются автоматически при `write()`.
- Корень обозначается `''` в `list()` и `has()`. Создавать или удалять корень нельзя.
- Значения сериализуются через `JSON.stringify()`. Нельзя сохранить значение, для которого результат сериализации — `undefined`; циклические объекты и `BigInt` вызывают ошибку сериализации. Предельный размер результата — 100 MiB в UTF-8.
- Виртуальные каталоги явно создаются методом `mkdir()`. Один путь не может одновременно быть документом и каталогом.

## `mtdb.open(filePath)`

Открывает существующий `.mtdb` или создаёт новый. Родительский каталог файла должен существовать. При открытии библиотека получает блокировку записи, при необходимости восстанавливает подтверждённые записи и индекс из журнала, затем строит в памяти индекс живых путей. Поэтому время `open()` зависит от размера журнала, а память — от числа путей.

Публичный `open()` принимает только формат файла v3. Для базы v2 сначала выполните отдельную офлайн-миграцию на **резервной копии**. Вызов `open()` сам не меняет v2 на v3. Файл неизвестной версии отвергается.

Успешное возвращение из `write()`, `delete()`, `mkdir()`, `rmdir()` или транзакции означает, что соответствующее изменение прошло предусмотренную запись и `fsync`. Фактическая сохранность после отказа питания зависит также от ОС и накопителя.

## Каталоги и поиск

### `db.mkdir(path)`

```js
db.mkdir('users/42');
```

Создаёт недостающие каталоги по порядку. Возвращает `true`, если создан хотя бы один, иначе `false`. Если промежуточный путь занят документом, возникает `path_is_file`. Создание нескольких каталогов не является одной транзакцией: при сбое часть родителей уже могла быть сохранена.

### `db.rmdir(path, options?)`

```js
db.rmdir('users/42');
db.rmdir('users/42', {recursive: true});
```

По умолчанию удаляется только пустой каталог; наличие любого документа или подкаталога вызывает `directory_not_empty`. Опция `{recursive: true}` удаляет всё поддерево и сам каталог **одной атомарной транзакцией**. Допускается только необязательное булево поле `recursive`.

Возвращает `false`, если каталога нет, `true` после успешного удаления; путь документа вызывает `path_is_file`. Для рекурсивного удаления действуют внутренние пределы: не более 100 000 дочерних записей плюс каталог и не более 128 MiB данных записей удаления. Превышение даёт `MTDB_TRANSACTION_TOO_LARGE` без частичного удаления. Числовой предел описывает внутренний журнал после согласованных правок; публичная `transaction()` по-прежнему ограничена 1000 путями.

### `db.has(path)`

```js
db.has('users');         // каталог
db.has('users/42.json'); // документ
db.has('');              // true: корень
```

Возвращает `true` для существующего документа или каталога, `false` для отсутствующего либо удалённого. Содержимое JSON не разбирается через `JSON.parse()`; проверка существующей записи может читать её с диска и проверять контрольную сумму.

### `db.list(path, options?)`

```js
db.list('');                         // документы в корне
db.list('users');                    // непосредственные документы
db.list('users', {recursive: true}); // все вложенные документы
```

Возвращает отсортированные полные пути **документов**, без путей каталогов. По умолчанию вложенные каталоги не обходятся. Для отсутствующего каталога возникает `directory_not_found`, для документа вместо каталога — `path_is_file`. Допускается только необязательное булево поле `recursive`. Выполняется полный проход данных и может быть дорогим на большом журнале.

## Документы

### `db.read(path)`

Возвращает разобранное JSON-значение либо `undefined`, если документа нет. Чтение пути каталога вызывает `path_is_directory`.

### `db.write(path, value)`

Создаёт или перезаписывает документ, возвращает `true`. Родительский каталог должен существовать; путь каталога нельзя перезаписать документом. Сериализация производится до записи на диск.

### `db.delete(path)`

Возвращает `true` для удалённого документа и `false` для отсутствующего. Для каталога возникает `path_is_directory`. После успешного удаления `read(path)` возвращает `undefined`, `has(path)` — `false`.

## Транзакции

```js
db.mkdir('archive');

const result = db.transaction(tx => {
  const user = tx.read('user.json');
  if (user === undefined) throw new Error('Документ не найден');

  tx.write('archive/user.json', user);
  tx.delete('user.json');
  return 'saved';
});
```

`tx.read()`, `tx.write()` и `tx.delete()` действуют внутри текущей транзакции; `tx.read()` видит уже подготовленные изменения. Изменения записываются лишь после нормального завершения обработчика. Если он выбрасывает ошибку, ничего из подготовленного не фиксируется. Результат `db.transaction()` совпадает с результатом обработчика.

Обработчик должен завершиться синхронно: `async` и возвращаемый `Promise` вызывают `MTDB_ASYNC_TRANSACTION_NOT_SUPPORTED`. Вложенные транзакции и вызовы обычных методов `db` внутри обработчика запрещены. `tx.mkdir()` и `tx.rmdir()` не существуют: каталоги для записей создавайте заранее.

Публичный предел — 1000 различных изменяемых путей и 128 MiB подготовленных данных вместе с накладными байтами записей. Превышение вызывает `MTDB_TRANSACTION_TOO_LARGE`. Успешная транзакция фиксируется целиком: восстановление не применяет её часть.

## Проверка, статистика и закрытие

### `db.verify()`

Полностью проверяет заголовок, метаданные, журнал, контрольные суммы, транзакции и соответствие индекса. При успехе возвращает объект:

```js
{
  valid: true,
  fileSize,
  metadataSlots,
  records,
  commits,
  files,
  directories,
  liveRecords,
  garbageRecords,
  liveBytes,
  garbageBytes,
  garbageRatio
}
```

При ошибке выбрасывает исключение; не исправляет подтверждённые повреждения. Полная синхронная проверка может занимать заметное время.

### `db.stats()`

Также выполняет полную проверку и возвращает `fileSize`, `records`, `commits`, `files`, `directories`, `liveRecords`, `garbageRecords`, `liveBytes`, `garbageBytes`, `garbageRatio` и `maintenanceError`. Последнее поле равно `null` или объекту `{code, message}` с ошибкой фонового обслуживания. Поля `valid` и `metadataSlots`, присутствующие в результате `verify()`, сюда не входят.

### `db.close()`

Первое успешное закрытие возвращает `true`, повторное — `false`. Освобождает блокировку и закрывает файл. После закрытия методы базы недоступны. Вызывайте `close()` в `finally`.

## Ошибки и восстановление

Методы выбрасывают исключения с `error.code`; некоторые ошибки проверки имеют `error.offset`, а исходная ошибка может находиться в `error.cause`. Точные значения кодов и порядок действий приведены в [ERRORS.md](ERRORS.md).

После ошибки записи исход операции иногда неизвестен: закрывайте экземпляр и открывайте файл повторно, затем проверяйте состояние данных. Если получен `recovery_required`, до повторного открытия нельзя продолжать чтение или запись. `MTDB_OPERATION_OUTCOME_UNKNOWN` означает, что индекс был восстановлен, но исход изменяющей операции не подтверждён; операция автоматически не повторяется.

Формат файла и правила восстановления описаны в [FORMAT.md](FORMAT.md).
